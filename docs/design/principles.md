# 好看、好用的设计原则

“好看、好用”为用户确认的要求。2026-10-25 用户选择 Docmost / Notion 作为参考，先制作 HTML 原型，再开始 P1 实现。当前参考原型为 `designs/nbase-v2`（Notion 家族三方向比较，用户选定方向 B「Notion × Outline」）；视觉令牌（颜色/圆角/阴影/双主题）集中在 `apps/web/src/shell/shell.css` 的 `--nb-*` 变量，持久化工作台与会话演示共用同一套 `nb-` 组件；正式前端代码位于 `apps/web`；原型与 P1 均使用会话内示例内容，最终组织方式仍待体验确认。

## 视觉方向提案

- 内容优先：侧边栏找内容，中央阅读写作，辅助信息按需出现。
- 统一字体、行距、间距、圆角、图标和选中态，避免各模块像不同产品。
- 文档保持舒适行宽；表格需要信息密度；白板需要空间，不用同一布局硬套。
- 低干扰背景和有限强调色，正文对比度、焦点和选区清楚。
- 不用装饰性仪表盘代替常用路径；未实现功能不摆无效按钮。
- 不依赖远程字体/CDN，NAS 无法访问第三方服务时仍能显示和操作。

## 第一条完整使用路径

创建文档 → 输入中文和格式内容 → 插入图片/普通表格 → 自动保存确认 → 切换并找回 → 导出 Markdown → 删除后恢复。

先让这条路径顺畅，再讨论白板和数据库的界面。评审覆盖空、加载、输入、保存、失败、离线、冲突和恢复状态。

## 交互底线

- 中文输入法、回车、退格、选择、撤销和粘贴可靠。
- 常用功能同时有可发现入口和键盘方式，不强迫记快捷键。
- 网络保存不阻塞输入；服务端确认后才显示“已保存”。
- 目录/标签切换不丢内容，重开能回到合理位置。
- 提示说明下一步能做什么，不在产品流程暴露无关实现细节。
- 字段、菜单、按钮文案统一；不以光标消失或全页刷新掩盖保存问题。
- 桌面主路径优先，窄屏应能阅读、导航、查看保存状态。

## 验证

用交互原型比较文档页、目录与编辑工具，由用户确认视觉方向。用真实写作任务验证，不只看截图。将中文输入、长文档、粘贴、断网恢复和键盘操作纳入发布检查。
