# 多维表格（数据库）首版

2026-11-07 交付。用户确认的范围有四项：

- 通用能力，暂不绑定具体业务场景；
- 行可以展开写正文（行即页面）；
- 首版只有表格视图；
- 数据库既是独立页面，也能嵌进文档。

2026-11-08 按用户确认的范围完成扩展，见下方“扩展”一节。本文记录契约和边界；验证结果见 [验证记录](../validation.md)。

## 扩展（2026-11-08，迁移 v14～v17）

**读取路径：** `POST /databases/:id/query` 在服务端筛选排序，返回全部行 ID 的顺序和第一窗内容；`POST .../rows/read` 按 ID 读取，每次最多 200 行。前端 `rowStore.ts` 保存顺序和窗口缓存。刷新后按需重读当前窗口及随后进入视野的旧缓存，单行或批量写入期间保留正在编辑的行。SQL 编译器在 `apps/server/src/databases/query.ts`，和 contracts 的 `evaluateView` 运行同一份 `resolveFilters` 结果，并有逐项对照测试。`POST .../aggregate` 计算页脚统计。

**工作区锁：** 不在锁内做 O(n) 工作。大库的搜索重建和计算字段放在 `databases/worker.ts` 的后台 worker，小批量处理，进度存在 `databases` 表和 `database_computed_dirty`，重启后续跑。计算 worker 用事务级咨询锁串行更新缓存。整库进回收站和恢复是例外，2.5 万行约 1 秒，期间其他写入排队。

**批量：** `POST .../rows/bulk` 支持 create、patch、trash、duplicate，每块最多 500 行，带操作收据。客户端按耗时调整块大小；CSV 导入用固定分块和固定操作 ID，失败后可在对话框里继续。

**筛选：** `view.filters` 的元素可以是条件，也可以是 `{ any: [...] }` 组。相对日期写成 `@this_week` 等，由 `resolveRelativeDate` 解析。半填的条件在分组前丢弃。时间按读者时区比较，时区两边都不认识时回退到工作区时区。

**视图：** 表格可冻结到某一列、页脚统计；看板按单选或复选框分组；日历按日期字段显示单日项目，每月最多 1000 行。

**关联：** 一对字段，`relation.owner` 为真的一侧把行 ID 存在 `row_properties`（每格最多 500），派生表 `database_row_links` 供对侧读取、筛选和排序。两侧都通过 `POST .../rows/:rowId/relations/:propertyId` 增删，实际写拥有侧的行并生成版本。普通写入接口拒绝写关联字段。

**公式和汇总：** 解析器在 `packages/contracts/src/formula.ts`，无 `eval`。公式只能引用本行的普通字段，汇总读关联行的字段或公式，因此没有循环。表达式按字段 ID 存储，改字段名不影响。单元格显示时实时计算，筛选、排序和统计读 `database_computed` 缓存。迁移 v18 为行级任务增加代次，并安排重算现有公式和汇总。worker 只清理自己处理过的代次，计算期间的新写入会保留在队列中。缓存未追上时查询返回 `computedStale`，依赖缓存的统计栏持续查询，直到收到最新结果。公式不含“今天”，因为缓存无法随时间过期。

**上限：** 每库 30,000 行。含行正文的 ZIP 最多 199 行，更大的库请导出 CSV 或使用完整备份。

**已知差异：** SQL 对 URL 的校验是模式近似；文本大小写折叠和排序依赖各自的 ICU 版本。

## 数据模型（迁移 v13）

- **页面类型**：`pages.kind` 取值为 `document`、`database` 或 `row`。
  - 数据库是页面树里的一种页面。
  - 行是数据库的子页面，所以正文、历史、搜索、回收站、反链、草稿和冲突处理都沿用页面那一套。
- **行的值**：存在 `pages.row_properties`（jsonb 对象，键为字段 ID）里，只有 `row` 有值，由 CHECK 约束保证。
  - 行标题直接使用 `pages.title`。
  - `page_versions.row_properties` 让历史快照包含字段值，历史恢复会同时恢复标题、正文和字段值。
- **结构与视图**：存在 `databases` 表（`properties_json`、`views_json`、`revision`），和行数据分开保存，不把业务数据塞进一个大 JSON。
- **备份**：`scripts/backup-engine.mjs` 对 schema v13 及以上的库纳入 `databases` 表。

## 字段与视图

**字段类型：** 标题、文本、数字、单选、多选、日期、复选框、网址、创建时间、更新时间（后两种只读，取页面时间）、关联、公式、汇总。人员、文件尚未实现。

**删除字段采用软删除：** 字段标记 `deletedAt`，行里的值保留，可以在「字段」面板恢复。

- 服务端拒绝从结构里直接移除字段，也拒绝改变标题字段的身份。
- 删除选项、更改字段类型都不改写行数据；与当前类型不符的值按空值显示和筛选，填入新值后才会替换。
- 选项保留在字段定义里，把单选或多选改成其他类型再改回来，选项和行值都会恢复。改类型时，比较选项的筛选条件和比较普通值的筛选条件互不适用，会被移除。
- 复选框未勾选算一个值，排序时跟随升降序。创建时间、更新时间按读者本地日期筛选，和单元格显示一致。

**视图：** 每个数据库最多 20 个视图（表格、看板或日历），每个视图独立保存以下内容：

- 筛选：所有条件同时满足；
- 排序：空值始终排在最后；
- 隐藏字段、字段顺序和列宽。

没有排序时按手动顺序显示（`sort_position`），可以拖动行调整顺序。

**上限：** 字段 100 个，每个字段的选项 200 个，每个数据库 30,000 行，每个视图的条件 20 个。

所有校验和 `evaluateView` 都在 `packages/contracts/src/databases.ts`，服务端、网页和演示模式共用同一份实现。

## 接口

所有接口都在 `/api/workspaces/:id` 下。

| 接口 | 说明 |
| --- | --- |
| `POST /databases` | 创建数据库页面，默认带「名称」标题字段和一个表格视图。父页面只能是普通文档。操作名 `database-create`，有操作收据 |
| `GET /databases/:pageId` | 返回结构、视图和前 2000 行；`?rows=none` 只返回结构，网页用这种方式 |
| `PATCH /databases/:pageId` | 整体替换字段和视图，带 `expectedRevision` 和 `clientMutationId`，修订不符时返回 409。字段定义变化时，会在同一事务里重算各行的搜索文本，但不增加行的修订号 |
| `POST /pages` | 父页面是数据库时，新页面自动成为行，可带初始 `properties` |
| `PATCH /pages/:id` | 带 `properties` 部分更新，`null` 表示清除。值按当前结构校验，不合格返回 422 `PROPERTY_INVALID` |
| `PUT /pages/:id/position` | 行排序，沿用页面排序接口 |

**页面规则：**

- 页面树不展开数据库，行不出现在侧栏，也不计入 2000 页上限。
- 不能把页面移进数据库，也不能把行移出数据库；数据库页面不接受正文。
- 复制页面接口不支持数据库和行；行通过批量接口的 duplicate 复制。
- 删除数据库会连同所有行一起进回收站。服务端核对 `expectedSubtreeIds` 时不要求客户端列出行。
- 数据库仍在回收站时，单独恢复其中一行会返回 409 `DATABASE_UNAVAILABLE`。

**搜索：** 行的 `search_text` 由正文，加上文本、网址、单选和多选的选项名派生。

## 前端

**`apps/web/src/database/`**

- `DatabaseView`：组合工具条和各视图。`toolbar/` 是工具条面板，`grid/` 是表格、窗口化、键盘光标、剪贴板和统计，`views/` 是看板和日历，`io/` 是 CSV 导入导出。
- `cells`：各类型单元格的显示与编辑。`OptionEditor`、`RelationEditor`、`ComputedEditor` 是字段配置。
- `RowPanel` / `RowProperties`：行页面上的属性面板。
- `source.ts`：`DatabaseDataSource` 接口和 `useDatabase` hook（只管结构，写入串行、总是带最新修订）。`rowStore.ts`：行的顺序、缓存和写入，每行的写入各自排队。成功写入后会通知同一数据库的其他打开视图重新读取。
- `persistentSource.ts`（API，响应丢失时用收据补查）和 `demoSource.ts`（会话内存）是两套数据源实现。
- 表格界面通过 `lazy.tsx` 按需加载，不进入主包。

**写入路径：**

- 打开的行页面里，属性修改走工作台的 `updatePageMeta`：先等待在途正文保存，再带当前修订提交，所以行的修订号和正文草稿不会互相覆盖。
- 表格里删除行，走持久的回收站操作（`beginPageAction`），保留操作 ID 以便重试。
- 新建数据库直接调用接口，网络中断时用收据补查；不写入本机待创建记录。

## 文档内嵌

**节点：** `database-view` 是顶层块级节点，只保存 `databaseId` 和可选的 `viewId`。

- 服务端只接受 UUID，且必须位于顶层。
- 节点内的编辑直接写入数据库，不产生文档修订。
- 宿主没有提供数据源时（历史预览、回收站预览），显示为占位块。

**插入：**

- `/数据库`：在当前文档下新建一个数据库并插入视图。
- `/关联数据库`：选择已有数据库并插入视图。
- 插入时会取代空的触发段落，避免留下 Markdown 无法表示的中间空段。

**Markdown：** 单独一行写成 `[数据库视图](/?page=<id>#nbase-database-view[=<viewId>])`。

- 只有整行匹配时，导入才还原为块；同样的链接出现在段落里时，保持为普通链接。
- 源码编辑按受保护往返处理这一行。

**事件隔离：** 节点内的输入、键盘和剪贴板事件会标记为 Lexical 已处理，所以 Ctrl+A、退格、回车只作用于单元格，不会改动正文。

## 边界与后续

- 真实业务数据的字段映射、权限和迁移仍需单独确认；本文的 3 万行容量只是合成数据上的结果，N150 上的表现还没有实测。
- 结构修改没有历史版本，只有修订号和操作收据；误删字段靠软删除恢复。
- 多选字段不能作为看板分组，日历不支持跨多天的项目，公式不能引用其他公式。
