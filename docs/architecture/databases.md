# 多维表格（数据库）首版

2026-11-07 交付。用户确认的范围有四项：

- 通用能力，暂不绑定具体业务场景；
- 行可以展开写正文（行即页面）；
- 首版只有表格视图；
- 数据库既是独立页面，也能嵌进文档。

本文记录契约和边界；验证结果见 [验证记录](../validation.md)。

## 数据模型（迁移 v13）

- **页面类型**：`pages.kind` 取值为 `document`、`database` 或 `row`。
  - 数据库是页面树里的一种页面。
  - 行是数据库的子页面，所以正文、历史、搜索、回收站、反链、草稿和冲突处理都沿用页面那一套。
- **行的值**：存在 `pages.row_properties`（jsonb 对象，键为字段 ID）里，只有 `row` 有值，由 CHECK 约束保证。
  - 行标题直接使用 `pages.title`。
  - `page_versions.row_properties` 让历史快照包含字段值，历史恢复会同时恢复标题、正文和字段值。
- **结构与视图**：存在 `databases` 表（`properties_json`、`views_json`、`revision`），和行数据分开保存，不把业务数据塞进一个大 JSON。
- **备份**：`scripts/backup-engine.mjs` 对 schema v13 及以上的库纳入 `databases` 表。

## 字段与视图

**字段类型：** 标题、文本、数字、单选、多选、日期、复选框、网址、创建时间、更新时间（后两种只读，取页面时间）。关联、公式、汇总、人员、文件尚未实现。

**删除字段采用软删除：** 字段标记 `deletedAt`，行里的值保留，可以在「字段」面板恢复。

- 服务端拒绝从结构里直接移除字段，也拒绝改变标题字段的身份。
- 删除选项、更改字段类型都不改写行数据；与当前类型不符的值按空值显示和筛选，填入新值后才会替换。
- 选项保留在字段定义里，把单选或多选改成其他类型再改回来，选项和行值都会恢复。改类型时，比较选项的筛选条件和比较普通值的筛选条件互不适用，会被移除。
- 复选框未勾选算一个值，排序时跟随升降序。创建时间、更新时间按读者本地日期筛选，和单元格显示一致。

**视图：** 每个数据库最多 20 个表格视图，每个视图独立保存以下内容：

- 筛选：所有条件同时满足；
- 排序：空值始终排在最后；
- 隐藏字段、字段顺序和列宽。

没有排序时按手动顺序显示（`sort_position`），可以拖动行调整顺序。

**上限：** 字段 100 个，每个字段的选项 200 个，每个数据库 2000 行，每个视图的条件 20 个。

所有校验和 `evaluateView` 都在 `packages/contracts/src/databases.ts`，服务端、网页和演示模式共用同一份实现。

## 接口

所有接口都在 `/api/workspaces/:id` 下。

| 接口 | 说明 |
| --- | --- |
| `POST /databases` | 创建数据库页面，默认带「名称」标题字段和一个表格视图。父页面只能是普通文档。操作名 `database-create`，有操作收据 |
| `GET /databases/:pageId` | 返回结构、视图和全部未删除的行（按手动顺序） |
| `PATCH /databases/:pageId` | 整体替换字段和视图，带 `expectedRevision` 和 `clientMutationId`，修订不符时返回 409。字段定义变化时，会在同一事务里重算各行的搜索文本，但不增加行的修订号 |
| `POST /pages` | 父页面是数据库时，新页面自动成为行，可带初始 `properties` |
| `PATCH /pages/:id` | 带 `properties` 部分更新，`null` 表示清除。值按当前结构校验，不合格返回 422 `PROPERTY_INVALID` |
| `PUT /pages/:id/position` | 行排序，沿用页面排序接口 |

**页面规则：**

- 页面树不展开数据库，行不出现在侧栏，也不计入 2000 页上限。
- 不能把页面移进数据库，也不能把行移出数据库；数据库页面不接受正文。
- 复制页面暂不支持数据库和行。
- 删除数据库会连同所有行一起进回收站。服务端核对 `expectedSubtreeIds` 时不要求客户端列出行。
- 数据库仍在回收站时，单独恢复其中一行会返回 409 `DATABASE_UNAVAILABLE`。

**搜索：** 行的 `search_text` 由正文，加上文本、网址、单选和多选的选项名派生。

## 前端

**`apps/web/src/database/`**

- `DatabaseView`：表格视图、工具条、表头菜单、列宽拖动、行拖动。
- `cells`：各类型单元格的显示与编辑。
- `RowPanel` / `RowProperties`：行页面上的属性面板。
- `source.ts`：`DatabaseDataSource` 接口和 `useDatabase` hook。结构写入串行执行、总是带最新修订；每行的写入各自排队。成功写入后会通知同一数据库的其他打开视图重新读取。
- `persistentSource.ts`（API，响应丢失时用收据补查）和 `demoSource.ts`（会话内存）是两套数据源实现。
- 表格界面通过 `lazy.tsx` 按需加载，不进入主包。

**写入路径：**

- 打开的行页面里，属性修改走工作台的 `updatePageMeta`：先等待在途正文保存，再带当前修订提交，所以行的修订号和正文草稿不会互相覆盖。
- 表格里删除行，走持久的回收站操作（`beginPageAction`），保留操作 ID 以便重试。
- 新建数据库直接调用接口，网络中断时用收据补查；不写入本机待创建记录。

## 文档内嵌

**节点：** `database-view` 是顶层块级节点，只保存 `databaseId` 和可选的 `viewId`。

- 服务端只接受 UUID，且必须位于顶层。
- 节点内的编辑直接写入数据库，不产生文档修订。
- 宿主没有提供数据源时（历史预览、回收站预览），显示为占位块。

**插入：**

- `/数据库`：在当前文档下新建一个数据库并插入视图。
- `/关联数据库`：选择已有数据库并插入视图。
- 插入时会取代空的触发段落，避免留下 Markdown 无法表示的中间空段。

**Markdown：** 单独一行写成 `[数据库视图](/?page=<id>#nbase-database-view[=<viewId>])`。

- 只有整行匹配时，导入才还原为块；同样的链接出现在段落里时，保持为普通链接。
- 源码编辑按受保护往返处理这一行。

**事件隔离：** 节点内的输入、键盘和剪贴板事件会标记为 Lexical 已处理，所以 Ctrl+A、退格、回车只作用于单元格，不会改动正文。

## 边界与后续

- 筛选和排序在浏览器内完成，服务端一次返回整个数据库（最多 2000 行）。现有约 2.5 万条业务记录远超这个规模，接入业务数据前必须改为服务端分页查询；首版不宣称支持大表。
- 数据库页面暂不提供导出。CSV 导入导出、看板等其他视图、关联、公式、汇总都留到后续。
- 结构修改没有历史版本，只有修订号和操作收据；误删字段靠软删除恢复。
