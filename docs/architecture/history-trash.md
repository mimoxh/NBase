# 历史与回收站契约

用户已确认：**每次成功保存留历史，暂不自动清理**。页面、历史、回收站与已提交附件都没有自动过期策略，也没有永久清空入口。后续按实际空间样例讨论保留上限，不能静默删除旧版本。

## 快照与恢复

- 迁移 v4 创建 `page_versions`，主键为 `(workspace_id, page_id, revision)`。快照包含标题、正文、格式版本、原父 ID、删除状态、保存时间、操作者和操作类型；迁移 v6 起额外保存当时的 `icon` 与 `cover`，仅作历史预览展示。
- 迁移只为已有页面保存当前状态的“迁移基线”，不增加页面修订或改更新时间。迁移前未保留的历史不能据此恢复。
- 创建、更新、删除/恢复子树、历史恢复的每个实际新修订，在同一事务中写入完整快照和操作收据。快照写入失败时整笔回滚；相同操作 ID 重试先返回原收据，不重复增加修订或历史。
- 历史恢复只恢复选中版本的标题和正文，保留当前目录位置、页面 ID 与当前 icon/cover（外观不回退）。必须提供当前 `expectedRevision` 和 `sourceRevision`；来源版本号参与操作摘要。恢复生成新修订，恢复前的当前内容仍留在历史中。未知正文格式拒绝恢复，原 JSON 可下载。
- 历史和附件读取继续校验当前工作区成员身份；viewer 可预览、不能恢复。恢复不会绕过当前页面写权限。附件按稳定 ID 引用，旧版本附件继续保留。

## 命名版本

- 迁移 v25 给 `page_versions` 增加 `label`（1～100 码点）与 `note`（1～1000 码点），约束 `page_versions_note_needs_label` 保证备注只能属于有名称的版本；部分索引 `page_versions_named_idx` 服务“只看命名版本”。旧版本两列为空，备份引擎按整行导出，无需改表清单。
- 命名、改名和移除名称只更新这两列：不增加页面修订、不写新快照、不产生操作收据。请求体是绝对状态，响应丢失后原样重试结果相同，因此不需要操作 UUID。已删除页面的历史版本同样可以命名。
- 服务端先去掉首尾空白，空白视为“无”；名称拒绝控制字符，备注允许制表符和换行，CRLF/CR 统一为 LF；两者都拒绝孤立代理字符。有备注而无名称返回 400。网页在发送前做同样的清理并显示字数。
- 恢复命名版本生成的新修订不继承名称。保存为命名版本时，网页先完成在途保存和草稿提交，再给保存后的当前修订命名。

## 列表与对比

- 网页按本地日期分组（今天、昨天、某月某日，跨年带年份）。同一天里相邻两次相隔不超过 5 分钟的未命名普通保存（`update`）折叠到最新一条，可展开；命名版本、创建、恢复和删除等操作单独显示。折叠只是展示，不合并或删除任何版本。
- 对比对象可选上一版本、当前版本或列表中的任意修订，总是按修订号从旧到新显示差异。上一版本不在已加载列表时，用 `beforeRevision` 和 `limit=1` 读取。差异仍由 `versionDiff.ts` 比较可见文字。
- viewer 可以浏览、筛选和对比，不能命名或恢复。
- 迁移 v29 起每个版本另存派生的 `search_text`，历史对话框可在本页全部版本中搜索标题和正文，全局搜索也可勾选同时搜索历史版本，见[页面搜索](search.md)。
## 回收站子树

删除将当前有效的选中页面及后代放入同一删除组。此前独立删除的后代保留原删除组。恢复任意选中页面时，仅恢复选中页面及同组后代，不恢复兄弟或独立删除的后代。原父页面不可用时，选中页面恢复到工作区根；内部后代父子关系和页面 ID 保留。同名页面并存，不按名称覆盖。

网页在确认删除时重新读取目录并检查目标子树中的本机草稿；目录变化时要求重新确认。提交包含 `expectedSubtreeIds`，服务端在工作区事务锁内比较实际子树，不一致返回 `PAGE_TREE_CHANGED`，避免预检后新移动进来的后代被一并删除。该字段在 API 中为可选兼容字段；网页始终提供，1～2000 个唯一 UUID。未提供的 API 调用使用提交时的实际子树。

## API

所有路径前缀为 `/api/workspaces/:workspaceId`，响应不缓存。读取要求会话和成员身份，变更另要求 Origin、CSRF 和写权限。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /pages/:pageId/history` | 按修订倒序列摘要（含 `label`、`note`），`beforeRevision` 游标，默认 50 条、最多 100 条；`named=true` 只列命名版本，其他取值 400 |
| `GET /pages/:pageId/history/:revision` | 读取单版完整预览，已删除页面也可读取历史 |
| `GET /pages/:pageId/history-search` | `q` 必填、`limit` 1～50（缺省 50），按修订倒序返回匹配版本摘要、保存人和高亮摘要，以及 `truncated`、`pendingVersions`；规则见[页面搜索](search.md)的“历史版本搜索” |
| `GET /history-search` | 全工作区历史搜索，每页一条最佳匹配版本，`limit` 缺省 20，可带 `tagIds` |
| `PUT /pages/:pageId/history/:revision/label` | 请求体 `{ label, note }`，设置或移除版本名称与备注，返回版本摘要；不改修订、无操作 UUID |
| `POST /pages/:pageId/restore-version` | 使用操作 UUID、当前修订和来源修订恢复标题与正文 |
| `GET /trash` | 按删除时间和 ID 倒序分页，默认 50 条、最多 100 条，返回所有已删除页面而非仅删除组根 |
| `GET /trash/:pageId` | 读取已删除页面正文及删除组信息 |
| `POST /pages/:pageId/trash` | 使用操作 UUID、当前修订及可选子树核对移入回收站 |
| `POST /pages/:pageId/restore` | 使用操作 UUID、当前修订恢复选中同组子树 |

## 浏览器保护

恢复历史或删除前先等待目标页的在途保存，再确认最新草稿已保存；与现有草稿相同的编辑器状态不重复标记为新更改。其他标签/会话的未处理草稿、待确认创建和附件上传会阻止操作。其他设备尚未提交的编辑无法由本浏览器提前检查，仍依靠修订冲突、本机草稿及服务端快照保护。

IndexedDB v3 的 `pending-actions` 保存账号、工作区、页面、操作、预期/来源修订、子树范围与操作 UUID，落盘成功后才发送变更。超时或服务失败先查收据，结果未知时保留记录、暂停相关页面自动保存；刷新或重登后可用同一 ID 重试。明确未提交的拒绝释放该记录，让用户重新检查后发起新操作。读取本机记录失败会暂停网络写入，但允许继续输入和下载当前正文。

预览使用独立只读编辑器及页面/修订身份，不接主页面的保存回调。恢复成功重新读取当前服务端状态；旧收据不会直接替换编辑器，迟到响应也不会把已切换到另一页面的正文换回。历史与回收站不能代替数据库和附件的一致备份。
