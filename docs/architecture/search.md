# V1 页面搜索契约

当前搜索只查**已保存到服务端且未进入回收站**的页面标题与正文。IndexedDB 中尚未确认的草稿不会出现在结果中；历史快照也不在本期检索范围。

## 索引与迁移

- PostgreSQL 迁移 v3 给 `pages` 增加 `search_text`。迁移在同一事务中分批回填已有页面；回填或版本校验失败，服务不开放写入。回填不增加文档修订，也不改变 `updated_at`。
- 创建和修订更新在原有页面事务中同时写入 `search_text`。索引文字从经过校验的 Lexical JSON 提取：相邻格式化文字连续，块之间分隔；内部附件的文件名及替代文本可检索。节点键、链接目标 URL、内部附件 ID、未显示的 JSON 字段不作为正文索引。
- 软删除后立即从结果中排除；恢复后使用原有索引重新出现。历史与回收站阶段不通过清理附件来维护搜索。

### 拼音键（迁移 v19）

- `pages.search_title_pinyin`、`pages.search_body_pinyin` 是 `tsvector` 派生列，可随时从 `title` 与 `search_text` 重建，不是正式内容。NULL 表示尚未建立，该页只走字面路径（下述 0、2、4 档），不会漏掉原有结果。
- 内容：标题全部汉字（最多 512 个 UTF-16 单元）；正文只取 `search_text` 开头 8000 个 UTF-16 单元。每个汉字占一个位置，其他字符的每段连续内容占一个分隔位置，所以只有紧挨着的汉字才算相邻，位置还能换算回原文偏移用于高亮。词元是无声调小写读音（ü 写作 v）：先用 `pinyin-pro` 的词语读音（银行 → yin hang），多音字再加最多两个其他读音（重庆 → chong / zhong）。每个词元最多记 255 个位置（PostgreSQL 上限 256），8000 单元之外的正文和超出的位置不建拼音键。
- 写入：创建、正文/标题保存和历史恢复在同一事务里由 `search/write.ts` 刷新对应列。触发器 `pages_search_pinyin_reset` 在任何 UPDATE 改变 `title` 或 `search_text` 时先把对应列清为 NULL，因此不知道拼音键的写入路径（数据库批量写入、行搜索文字后台重算、离线回填等）只会让该页暂时退回字面搜索，不会留下过期键。
- 回填：迁移只加列、触发器和部分索引 `pages_search_pinyin_pending_idx`（`WHERE` 任一列为 NULL），不在迁移事务或工作区锁内计算。服务启动后 `search/worker.ts` 每批取 25 行，`FOR UPDATE SKIP LOCKED` 只锁这些页面行，读取标题和正文前 8000 字符，算完写回；进度就是这些 NULL 列，重启后接着做。空闲时每 5 秒检查一次，出错 30 秒后重试。以后如果改变注音规则，新迁移把两列清空即可让后台重建。
- 备份：两列属于 `pages`，跟随表内容摘要和 `pg_dump` 一起备份恢复，备份清单不需要单独登记；恢复后数据与原库一致，无需重建。

## 查询与界面

- `GET /api/workspaces/:workspaceId/search?q=...&limit=...` 必须有有效会话和工作区成员身份，viewer 可搜索。查询最长 100 个 UTF-16 单元、256 UTF-8 字节，不含控制字符；`limit` 为 1～50，缺省 20。响应包含最多 `limit` 条摘要与 `truncated` 标记，不返回完整正文。只匹配标题与 `search_text`，不在 JSON、URL 或内部 ID 中匹配。
- 分词（`search/query.ts`）：先按空白切分；纯中文片段再用 `Intl.Segmenter('zh', { granularity: 'word' })` 分成词（项目计划 → 项目、计划）；同时含汉字和字母的片段（项目jihua）保持整体；去重后最多 8 个词。含空格的中文查询另有去掉空格的紧凑写法（项目 计划 → 项目计划）。
- 拼音词：含字母的词解析为拼音单元，每个单元是整音节、音节前缀（输入一半或首字母）或查询里的汉字（取其全部读音）。整串字母取单元最少的两种切分，另加全首字母读法（xmjh），最多 3 种，以 `<->`（相邻）组成 `tsquery`，词元只含 a～z，直接按 `::tsquery` 传参，不经过解析器。只有一个音节的词（hua、an）不做拼音匹配；含数字或其他符号的词只按字面匹配。多个拼音词另合成一个整体短语用于排序。
- 相关度（`search/search.ts`），从高到低：0 标题完全相同；1 标题前缀；2 标题包含查询；3 标题包含全部词；4 正文包含查询；5 标题或正文包含全部词（先看是否按顺序相距 24 字以内，再看词频，只统计正文开头 4000 字）；6 每个词都能在标题中按字面或拼音找到；7 每个词都能在标题或正文中按字面或拼音找到。6、7 档里连续拼音短语和较短标题在前。同档按最近更新、ID 排序。字面匹配都是不区分大小写的子串（`position`），`%`、`_` 不当通配符。0、2、4 档就是原来的字面搜索，所以原来能搜到的页面仍然都在结果集合里；但词语或拼音匹配更好的页面可能排在前面，结果超过 `limit` 时通过 `truncated` 提示缩小范围。
- 摘要与高亮：结果的 `highlight` 是在 `matchField` 中实际出现的文字，与查询不同时才返回，例如拼音匹配到的汉字（xmjh → 项目计划）或分开出现时最先出现的词。拼音位置由第二个查询从命中页面的 `tsvector` 取回，再换算回原文。摘要以该文字为中心，找不到时用正文开头。
- 网页工作台显示标题、短摘要和 30 条上限提示，标记和打开时优先用 `highlight`。输入防抖 250ms；切换关键词会取消旧请求并忽略旧响应；中文输入法组词期间不提交搜索。空白、加载中、无结果、失败和重试有独立状态。`Ctrl/Cmd+K` 打开搜索。
- 打开结果走现有页面切换路径，当前编辑先进入本机草稿和保存队列。标题命中聚焦标题；正文命中仅移动 DOM 选区或滚动到内部附件，不修改 Lexical 文档。若页面在查询后改变，打开失败或词句在当前草稿中已不存在，给出提示，不覆盖当前编辑。
- 编辑器内的斜杠菜单只用静态拼音别名（见 `docs/product/editing-commands.md`），不加载字典。`[[` 页面选择器和演示工作台搜索仍只做字面匹配。

## 查询计划与性能

- 查询按 `workspace_id` 取出该工作区的未删除页面，逐行计算档位：每行只对标题、正文各做一次 `lower()`，档位子查询用 `OFFSET 0` 隔开，避免 PostgreSQL 把 CASE 展开后多次计算；先排出 `limit + 1` 个 ID，再只为这些页面读取正文。拼音判断是对每行 `tsvector` 的 `@@`，只有字面档都未命中时才计算。
- 没有加 GIN 索引：查询把不可索引的子串条件和拼音条件用 OR 组合，规划器仍要逐行检查，GIN 用不上；首字母查询（`x:*` 这样的前缀）几乎对所有中文页面都命中，用索引预筛也没有选择性。字面子串仍然是顺序扫描，与原有方案相同。唯一新增的索引是回填用的部分索引。
- 测量：本机没有可用的 `NBASE_TEST_DATABASE_URL`（127.0.0.1:54329 无法连接），未在正式基线的 PostgreSQL 18 上测量，`test:db` 也未运行。改在 PGlite（WebAssembly 版 PostgreSQL 17，单线程，明显慢于原生）上用合成数据对比：504 页、最大 720 KB、9 页 100 KB、其余 2～14 KB 中英文混排。原字面查询中位数约 90～150 ms，新查询：无命中 1.0～1.1 倍，一般词和拼音 1.2～1.7 倍，"项目计划"这类大多数页面都同时含两个词的查询约 2 倍（多出的是第 5 档评分）。按 P3-06 原生基线 15～31 ms 推算，新查询大约在 20～60 ms，仍需在正式环境复测；回填 504 页约 4 秒（WebAssembly）。

## 范围

无需外部搜索服务、分词扩展或 PostgreSQL 额外扩展（zhparser 不可用；pg_trgm 未使用）。不支持同义词、拼写纠错、历史版本搜索、正文 8000 单元之后的拼音匹配，以及单个音节的拼音查询。页面数量明显增长或换到 NAS 后需复测。
