# 子页面树契约

基线日期：2026-10-25；更新：2026-10-27。用户确认 V1 使用“页面可包含子页面”的组织方式；本机持久化 API、事务与回收站恢复已有验证，具体结果见 [验证记录](../validation.md)。

## 页面身份与父子关系

V1 只有一种页面实体。每页有稳定 `id`、所属 `workspaceId`、可空 `parentId`、标题、版本化正文、`revision`、创建/更新时间和软删除状态。`parentId = null` 表示工作区根页面；页面既能包含正文，也能包含子页面，不另设文件夹表。页面移动、改名、删除与恢复不改变自身或后代的 `id`。

父页面必须在同一工作区且未删除。不能以自己或任意后代作为父页面，不能在不同工作区之间靠修改 `parentId` 偷换归属。服务端需要数据库约束检查自身父子关系，并在事务中验证更深的环；前端隐藏无效目标只是辅助。为防止两个标签同时移动造成环，树结构变更先锁住该工作区的树写入序列，再检查父链和修订，最后更新。

标题允许为空，界面显示“未命名页面”；同一父页面下允许重名，操作以稳定 ID 标识目标。V1 不承诺手动同级排序，默认以创建顺序及 ID 组成稳定顺序。最近打开属于用户/工作区访问记录，不改变页面层级。后续多人使用时，共享规则仍需独立确定，不因为同一工作区字段自动开放给其他用户。

## 更新、删除与恢复

创建页面由服务端生成 ID；每一次写入都携带 `clientMutationId`（UUID），服务端在同一事务中保存请求摘要与结果。相同标识、相同请求的重试返回原结果；相同标识配不同请求须拒绝，避免超时后的重复创建或误写。修改标题、正文或父页面均携带十进制字符串 `expectedRevision`（对应 PostgreSQL `bigint`），成功才增加修订并返回字符串修订；旧修订返回 409，不能无提示覆盖。正文 `schemaVersion` 未知时拒绝更新并保留原数据。每个业务接口先校验会话和工作区权限。

删除页面时把它和当时仍有效的后代放入同一删除组，原本已删除的后代保持自己的删除组。恢复某个选中的页面时，只恢复它和同一删除组内的后代；同组的兄弟页面保持已删除，之前独立删除的后代也不被复活。若选中页面的原父页面仍已删除或不存在，则把选中页面恢复到工作区根并提示；被恢复后代保留内部父子关系。此行为与 P1 工作台一致。恢复保留页面 ID，不得覆盖更新过的修订；历史恢复另按新修订处理。回收站永久清理及附件引用规则属于 P3，V1 正式使用前还要完成相应恢复演练。

所有列表与搜索必须限制在授权工作区，返回数量有明确上限或游标。树节点很多时按父页面分页/按需展开；不把全工作区一次载入作为长期接口契约。数据库迁移、树写入事务、并发移动和软删除恢复需要真实 PostgreSQL 集成测试，前端 reducer 测试不能替代它们。

## 存储与历史

`pages(id, workspace_id, parent_id, title, content_json, content_schema_version, revision, created_at, updated_at, deleted_at, deletion_group_id, search_text)` 保存当前状态；`page_versions` 保存每个实际新修订。服务端校验节点白名单、大小与深度，不只信任 JSONB 可解析。删除前网页刷新目录、检查目标子树草稿，并提交预期子树 ID；服务端在工作区事务锁内核对范围，变化时拒绝。历史、回收站、附件与待确认操作的规则见 [历史与回收站](history-trash.md)。
