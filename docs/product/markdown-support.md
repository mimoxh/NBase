# Markdown 支持矩阵（P1）

更新：2026-10-26。本文描述实际实现边界，不把配置完成等同于浏览器验收。文档内容以 `schemaVersion: 1` 的 Lexical JSON 为编辑状态，Markdown 是导入、导出与只读查看形式。P1 不承诺任意 Markdown 源文件无损重排，也不提供源码双向编辑。导入对话框可下载原文；创建页面后当前持久化工作台不保存原始文件字节，应自行保留原文件。结构化导出不是原文件备份。

## 明确限制

- GFM 表格只支持普通矩形、单行单元格。合并、嵌套、多段内容、单元格内列表/代码块不属于 Markdown 表格往返保证。HTML 表格不能默默变成普通 GFM 表格。
- 结构化导出规范化列表标记、空行、格式标记及表格布局；原始字节、任意空白和任意方言不能保证。持久化工作台以页面标题命名 `.md` 文件，文件正文只含编辑器正文，不重复插入页面标题。导入时以文件名建立页面标题；浏览器对重名下载增加的 `(1)` 等后缀也会成为标题。原始导入文本只在导入对话框中供查看和下载，创建后请保留源文件。
- 检测器偏向保全内容。复杂格式与普通文本混合时，整篇降级成可编辑 Markdown 代码块；不冒险局部转换。检测不是覆盖所有 Markdown 扩展的完整语法解析器，未识别语法通常保持文本。应始终保留原文件。
- 外部 Markdown 图片节点只保存引用和替代文本，不创建 `img`，不请求远程 URL。P3 新增的上传附件使用另一种稳定 ID 节点，由同源授权 API 加载图片。复杂目标（例如未转义嵌套括号）、引用式图片等降级原文。页面 ZIP 导出仍不是数据库、历史与附件目录的完整备份。
- URL 仅允许 `http`、`https`、`mailto` 与普通相对路径/锚点；空 URL、控制字符、反斜线、协议相对地址与其他显式协议被拒绝。危险链接保留文字而不创建可点击链接。应用层仍需拦截粘贴和点击，不只依赖 Markdown 转换器。
- 大纲 ID 为 `heading-${node.getKey()}`，只用于当前视图锚点；重新解析 JSON 后 key 可变化，不能用作持久业务 ID。
- 此模块不负责持久化、版本迁移、权限或业务文档 ID。未知 `schemaVersion` 的拒绝与文档切换失败时保留原状态，由编辑器容器负责。

## 固定样例与已运行测试

固定样例在 `docs/fixtures/markdown/`：

- `common.md`：标题、行内格式、链接、引用、嵌套列表、任务、代码、分割线。
- `table.md`：三列表格、左右居中对齐、普通和行内代码中的转义管道、粗体、链接。
- `unsupported.md`：HTML 合并表格、脚本字符串、脚注、引用式链接。
- `malformed-table.md`：额外单元格不可被静默丢弃。

## 尚需浏览器验收

- Windows 中文 IME 连续输入、候选确认、组合过程中空格/回车、组合完成后的 Markdown 转换；不得重复插入或吞字。
- 输入标题、列表、代码、分割线和行内格式后的撤销/重做；列表 Tab/Shift+Tab、任务复选框、表格焦点移动。
- 导入文件前显示能力警告，确认原文降级后内容仍可复制，原文件下载与结构化导出明确区分。
- 粘贴 HTML/复杂表格的安全降级、点击危险链接被拦截、图片占位不发起请求。
- 页面切换、源码只读查看、大纲定位、错误边界与未知 schema 的保全行为。

参考：[Lexical Markdown 官方说明](https://lexical.dev/docs/packages/lexical-markdown)。实际实现同时对照锁定版本 0.52.0 的类型声明与转换器源码。
