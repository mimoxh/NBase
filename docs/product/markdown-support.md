# Markdown 支持矩阵

更新于 2026-11-05。文档内容以 `schemaVersion: 1` 的 Lexical JSON 为编辑状态，Markdown 用于导入、导出与受支持范围内的源码编辑。导入对话框可下载原文，创建页面后请保留原始文件。阶段实测见 [验证记录](../validation.md)。

## 能力矩阵

“快捷输入已配置”表示转换器接入后具备对应规则；真实键盘、撤销与中文输入法需要单独浏览器验收。

| 列数不一致的表格、复杂/不完整图片语法 | 不提供自动修复 | 警告并整篇原文保留 | 代码围栏原文 | 可查看 | 不静默丢弃额外列或图片 URL |

## 明确限制

- 源码面板提供预览、应用、取消和复制，只编辑正文。标题、标签和 YAML 元数据继续由页面及导入设置管理；已有元数据在应用时保全。原正文或输入不能语义往返时阻止应用，可复制输入或查看保留的原始 JSON。
- 源码上限 2 MiB（含 Markdown 转义），转换后的 JSON 仍遵守 1 MiB、20,000 节点和 64 层限制。应用只生成一次可撤销编辑，后续保存与修订冲突沿用工作台流程。源码草稿按账号、工作区、页面和编辑实例隔离，取消保留草稿，明确放弃或成功应用才按版本清理。
- 图片宽度、对齐和图注不写入 Markdown，源码面板按附件 ID 保留；同一图片的相同写法带不同属性时无法区分，阻止应用。导出时图注成为图片下方的段落，NBase ZIP 的清单保留完整属性。
- 附件源码保留原 ID 及已知元数据，可修改图片替代文字；新增未知附件 ID、修改文件名、图片/文件语法互换或附加 Markdown title 会阻止应用。持久化工作台在应用前验证附件授权与文件。外部图片仍只显示占位。
- “随手记”章节在源码中带 `<!-- nbase-quick-capture -->`。可整体移动原标记和标题；删除、重复、单独移走标记或改写该受保护标题会阻止应用。标题改名可在普通编辑器完成，持久标记随之保留。
- 文字颜色、段落对齐和折叠块使用固定的 HTML 子集往返：`<span style="color:#…;background-color:#…">`（只接受 9 种调色板颜色的浅色值）、单独成段的 `<div align="center|right|justify">` 包住段落或标题，以及 `<details>` + 下一行 `<summary>…</summary>`。只有这几种写法会转换，其他 HTML、未知颜色、未闭合或跨行的标签仍整篇保留为原文。对齐只用于正文段落和标题，表格单元格沿用 GFM 列对齐，列表、引用和折叠块标题不对齐。折叠块的展开状态是视图状态，按页面在本机保存，不进入正文。
- Markdown 不表达的正文属性（例如首行缩进、下划线、行高、多段或保留首尾空格的单元格）会触发源码应用保护。不会为了允许应用而丢弃这些属性。
- 网页书签导出为 `<!-- nbase-bookmark site="…" description="…" -->`（百分号编码）加下一行的 `[标题](<网址>)`，导入时两行必须相邻且第二行只有一个 http/https 链接，否则整篇保留原文。
- GFM 表格只支持普通矩形、单行单元格。合并单元格和列宽写在表格上方一行 `<!-- nbase-table widths="120,200" spans="行.列=宽x高,…" -->`，下面仍是完整 GFM 网格，被合并覆盖的位置留空；注释与表格不匹配、覆盖位置有文字或合并区域重叠时整篇保留原文。含合并单元格的表格不能整行或整列移动。嵌套、多段内容、单元格内列表/代码块不属于往返保证。HTML 表格不能默默变成普通 GFM 表格。
- 表格单元格内行内公式的 LaTeX 源码若含 `\|`（LaTeX 竖线记号），导入时先被表格管道反转义吃掉反斜线，源码成为 `|`；导出重新转义后 Markdown 字节一致，但无法区分作者写的是 `\|` 还是 `|`。需要竖线语义的公式请写在表格外。
- 结构化导出规范化列表标记、空行、格式标记及表格布局；原始字节、任意空白和任意方言不能保证。持久化工作台以页面标题命名 `.md`，front matter 保存标题，正文不重复标题。导入优先有效 YAML title，否则使用文件名。原始导入文本可在导入对话框或批次中取回，仍请保留源文件。
- 检测器偏向保全内容。复杂格式与普通文本混合时，整篇降级成可编辑 Markdown 代码块；不冒险局部转换。检测不是覆盖所有 Markdown 扩展的完整语法解析器，未识别语法通常保持文本。应始终保留原文件。
- 外部 Markdown 图片节点只保存引用和替代文本，不请求远程 URL。上传附件使用稳定 ID，由同源授权 API 加载。引用式图片遵循相同规则，不能可靠解析的复杂目标保全原文。页面或子树 ZIP 不能替代数据库、历史与附件目录的完整备份。
- URL 仅允许 `http`、`https`、`mailto` 与普通相对路径/锚点；空 URL、控制字符、反斜线、协议相对地址与其他显式协议被拒绝。危险链接保留文字而不创建可点击链接。应用层仍需拦截粘贴和点击，不只依赖 Markdown 转换器。
- 大纲 ID 为 `heading-${node.getKey()}`，只用于当前视图锚点；重新解析 JSON 后 key 可变化，不能用作持久业务 ID。
- 此模块不负责持久化、版本迁移、权限或业务文档 ID。未知 `schemaVersion` 的拒绝与文档切换失败时保留原状态，由编辑器容器负责。

## 固定样例与已运行测试

固定样例在 `docs/fixtures/markdown/`：

- `common.md`：标题、行内格式、链接、引用、嵌套列表、任务、代码、分割线。
- `table.md`：三列表格、左右居中对齐、普通和行内代码中的转义管道、粗体、链接。
- `callout-highlight.md`：提示块类型、自定义标题、多段正文、未知引用标记和行内高亮。
- `unsupported.md`：HTML 合并表格、脚本字符串、脚注、引用式链接。
- `malformed-table.md`：额外单元格不可被静默丢弃。
- `notes-mixed.md`：A–D 混合格式和元数据的语义往返出口。
- `mermaid.md`：流程图、时序图及错误/交互指令的诊断样例。

2026-10-25 在独立 worktree、Node 24.19.0 / Lexical 0.52.0 环境执行：

- `npm run build --workspace @nbase/contracts`：通过。
- `npm run typecheck --workspace @nbase/web`：通过。
- `npm run test --workspace @nbase/web -- src/editor/markdown.test.ts`：34 项通过。
- 测试使用 Lexical `createEditor`，无需 DOM、网络或 `@lexical/headless`。验证 JSON 再开、Markdown 二次往返、节点类型与结构、危险链接、原文保全和中文字符串。中文字符串测试不等于中文 IME 实测。
- 独立 worktree 前端构建碰到旧 HEAD 残留 `postcss.config.js` 查找已废弃的 Tailwind 依赖；未改动不属于本模块的旧配置。最终构建结论以集成目录的全阶段检查为准。

## 浏览器覆盖与保留项

- A–E 批的桌面 Edge 自动化覆盖查找替换、折叠、TSV、导入提示、附件与引用重建、脚注、图表、源码只读预览/应用/撤销、双标签草稿、断线重登和冲突另存，实际记录见 [验证记录](../validation.md)。
- Windows 实体中文输入法候选操作仍需人工复测；自动化组合事件覆盖不能替代实体输入法。原 P1 键盘与移动设备清单中未记录的项目继续保留，不能据此宣称跨设备全部通过。

参考：[Lexical Markdown 官方说明](https://lexical.dev/docs/packages/lexical-markdown)。实际实现同时对照锁定版本 0.52.0 的类型声明与转换器源码。
