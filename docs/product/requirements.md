# 已确认需求与沟通记录

初始记录：2026-10-24；补充：2026-10-25（Asia/Shanghai）。按主题整理沟通结果，不把助手建议自动视为用户承诺。

## 1. 产品目标：用户已确认

NBase 是用户自己开发、自部署的知识与业务工作台，长期用于日常笔记，并逐步容纳业务数据。用户明确强调：**重要的是好看、好用**。核心使用能力不应依赖按席位购买商业授权或强制使用第三方 SaaS。

长期目标已经确认：

- 文档和笔记，支持 Markdown。
- 多维表格，用于结构化记录业务数据；不是仅在文档里放一个普通表格。
- 双向链接，建立内容间的引用和反向引用。
- 白板，用视觉方式组织内容。
- 业务数据可以保存在同一软件内。
- 可自部署，并可在外网访问。（2026-11-03 用户决定放弃外网访问验收 P3-07；当前不验证也不宣称外网可用。）

产品不要求一次复刻完整飞书。聊天、视频会议、邮件、完整 Office 文件兼容没有成为确认需求。

## 2. 最新阶段决定：用户已确认

- 当前目录允许删除旧实现并重新构建，从技术选型开始。
- 2026-10-24 的交付范围是**项目初始化和简单项目计划，完整记录沟通细节**；2026-10-25 用户先要求丰富计划，随后授权执行 P1 文档体验验证。
- **第一版只打磨文档功能**，其他能力以后逐步实现。
- 暂时不重点考虑三人同时编辑同一份内容。
- Markdown 采用用户选择：**以好用的编辑器为主，支持 Markdown 导入、导出和源码查看**。
- 不要求每篇笔记以 `.md` 文件作为唯一内部真值源。
- 源码“查看”已确认；任意源码直接修改并无损往返尚未确认，不能默认追加。

2026-10-25 补充确认：**V1 先供个人使用，预留多人能力**。此前“最多约三人同时使用”保留为未来背景，不要求 V1 交付多人工作区、邀请成员、共享或实时协作。个人使用仍需登录和服务端授权，也仍需处理同账号多标签、跨设备的版本冲突。

2026-10-25 补充确认：用户选择 [Docmost](https://docmost.com/docs/) 和 Notion 作为视觉与操作参考，并要求先制作 HTML 展示整体前端，随后授权开始执行计划。采用低干扰侧栏、页面树和宽松正文排版；这不表示照搬参考产品全部功能。用户进一步确认 **沿用“页面可包含子页面”的组织方式**，不建立单独的文件夹对象作为 V1 文档目录。

## 3. 当前环境与业务背景

| 项目 | 用户提供的情况 |
| --- | --- |
| 部署设备 | NAS，Intel N150、16GB 内存，与其他容器共享资源 |
| 使用人数 | V1 个人优先、预留多人（2026-10-25 确认）；长期背景为最多约三人同时使用，实时共同编辑不是当前重点 |
| 当前业务系统 | NocoBase + PostgreSQL |
| 数据规模 | 约 25,000 条业务记录，主要做登记、编辑、查询 |
| 已有相关工具 | 容器列表包含 Memos 等多个自部署服务 |

历史采样中，NocoBase 约 592MiB、PostgreSQL 约 150MiB；NAS 界面报告约 4.76GB 可用内存。Swap 接近 4GB 满额，但 vmstat 采样除开机平均行外没有换出、仅少量换入。这些是历史瞬时观察，不是 NBase 的资源保证或性能基准。

本轮没有 NAS 访问权限，也不操作当前业务数据。后续迁移前必须备份并验证副本，不能将 CSV 导入成功等同于业务完整迁移。

## 4. 已讨论的关键取舍

1. CRM 面向客户和销售生命周期，当前登记场景可继续用 NocoBase；本项目不必先实现完整 CRM。
2. 单独文档平台难以同时满足多维表格、双链、白板和业务数据一体化，因此决定自行开发。
3. 普通文档表格、多维表格、Excel 工作簿是三类能力。V1 可包含普通表格，不暗含另外两类。
4. 文档、记录和白板通过稳定对象标识建立关系，不复制成三个互不关联的数据孤岛。
5. 不实时共同编辑也存在跨设备、跨标签旧版本覆盖，正式保存需要修订检查。
6. 使用成熟开源编辑器和绘图基础，开发重点是交互、整合和数据可靠性。
7. 现有 2.5 万条业务记录不在本轮迁移；NocoBase 先保留。

## 5. 本轮技术决定：与用户需求区分

这些是为落地最新需求作出的工程选择，理由和可逆性见技术决策文档：

- 网页优先，NAS 服务端持久化正式内容；浏览器保留恢复草稿。
- React / TypeScript / Vite + Node.js 24 LTS / Fastify。
- Lexical 作为文档编辑器内核，原生 JSON 保留完整内容；Markdown 作为输入与交换格式。
- PostgreSQL 作为计划中的数据库，附件放持久化目录。
- 初始化不引入 Redis、独立搜索服务、消息队列、微服务或桌面壳。
- 先以桌面浏览器为主要编辑环境，提供手机阅读与基础操作适配；完整移动编辑需实测决定。

以上不表示相应功能已实现。

## 6. 被旧规划扩大的内容：不属于 V1 承诺

旧目录曾包含全面 local-first / 完整离线读写、CRDT、协作光标、日程提醒、Today、完整项目管理、工作负载、路线图，以及大量数据库字段和视图。这些不再作为当前实施基线。

- 完整离线读写、多设备自动同步：后续候选。
- 实时协作、复杂权限、公共分享：按实际需要分阶段评估。
- 日程提醒、项目依赖、资源负载等：候选扩展，尚未决定实现。
- 多维表格、双链、白板：保留为已确认长期目标，但不提前承诺全部旧 PRD 细节。
- 原性能报告引用当前不存在的目录，不沿用其完成度或性能结论。

## 8. 长期整合场景

业务记录可以打开成详情文档；笔记引用业务记录；白板通过引用卡片打开源文档或记录。重命名不破坏引用，删除显示可恢复或失效状态。该场景指导稳定 ID 与引用边界，不要求初始化时建立万能对象框架。
