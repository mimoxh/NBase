## 发现

### P2：模板失败写入的正文与操作 ID 随弹层关闭丢失

位置：[NoteTemplateDialogs.tsx](../../apps/web/src/persistence/NoteTemplateDialogs.tsx)，`pending` 定义在 144 行，操作保留在 170 行，异常后释放 busy 在 188～195 行，关闭入口在 216、240 行。

复现：打开「笔记模板」→「新建个人模板」，填写名称和独有正文 → 浏览器断网 → 保存 → 出现「保存结果尚未确认」→ 关闭 → 恢复网络并刷新 → 重开模板。

结果：待提交正文、操作 ID 和「重试」入口均消失。浏览器实测确认该请求未在服务器创建模板，IndexedDB 也没有正文副本。模板编辑器使用 `ignoreChange`，没有进入页面草稿链；`pending` 只是 React state，卸载后无法恢复。

修复方向：在首次请求前持久化模板正文和原操作 ID，按账号/工作区恢复未知结果并沿用同 ID 重试；成功后按版本清理。关闭和刷新都需要覆盖，仅阻止关闭不足以处理刷新恢复。

### P2：工具栏新建的普通表格阻止整页源码应用

位置：[ToolbarPlugin.tsx:151](../../apps/web/src/editor/plugins/ToolbarPlugin.tsx) 与 [sourceEditing.ts:260](../../apps/web/src/editor/sourceEditing.ts)。

复现：打开普通页面 → 工具栏「插入 3 × 3 表格」→「Markdown 源码」→ 在表格外增加正文。

结果：显示「原始正文含 Markdown 不能完整表达的结构或属性」，「应用」一直禁用。`includeHeaders: true` 同时生成首行和首列表头，表头状态为 `[[3,1,1],[2,0,0],[2,0,0]]`；GFM 导入只重建首行，变成 `[[1,1,1],[0,0,0],[0,0,0]]`，使安全往返比较失败。这会影响常规工具栏创建的表格所在整页，已有正文仍被保护。

修复方向：统一新建表格与既有 GFM 首行表头契约，例如显式指定 `{ rows: true, columns: false }`，并保持对已有无法表达属性的保护。补覆盖“工具栏插表 → 源码修改 → 应用/撤销”的集成用例。
